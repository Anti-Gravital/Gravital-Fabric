# PRODUCT loop: from real usage to feature proposals / Loop PRODUCT: del uso real a propuestas de features

1. Read `docs/kaizen/data/insights/latest.json` (usage, errors, performance)
   and issues labelled `feedback`. Lee los insights y los issues con etiqueta
   `feedback`.
2. Identify patterns: heavily used features with friction, flows with many
   errors, never-used features, repetitive tasks that could be automated.
   Identifica patrones: funciones muy usadas con friccion, flujos con muchos
   errores, funciones nunca usadas, tareas repetitivas automatizables.
3. Draft up to three proposals in `docs/kaizen/proposals/NNNN-title.md`:
   problem, evidence (numbers from insights), minimum solution, success
   metric, risks, privacy and RICE score.
   Redacta hasta 3 propuestas en `docs/kaizen/proposals/NNNN-titulo.md`:
   problema, evidencia, solucion minima, metrica de exito, riesgos, privacidad
   y puntuacion RICE.
4. Open one issue per proposal with the `proposal` label, not `kaizen:ready`.
   A person decides whether it becomes ready. Abre un issue por propuesta con
   la etiqueta `proposal`, no `kaizen:ready`. Una persona decide si pasa a
   `kaizen:ready`.
5. Do not implement features without that approval, at any autonomy level.
   No implementes features sin esa aprobacion, en ningun nivel de autonomia.
